# 📐 Guideline for UI/UX

## 1. 前提（ユースケース・UX理論）

### 典型的なユースケース
- AさんとBさんが共同で生活費や旅行費を管理  
- 支出をその場でサクッと登録（誰が・何に・いくら）  
- 後で「どちらが多く払ったか」「清算額」を一目で把握  
- 清算済みは隠してすっきり見えるように  

### 関連するUX理論
1. **Fittsの法則**  
   人は「近くて大きなターゲット」を素早く正確にタップできる  
   → よく使う操作（保存・追加・決定）を大きく・親指の届きやすい場所に配置  

2. **Hickの法則**  
   選択肢が増えると意思決定に時間がかかる  
   → カテゴリを絞る / 最近使ったカテゴリを優先表示でタップ数削減  

3. **認知負荷理論**  
   人間の短期記憶は少ない（7±2）  
   → 不要な入力を自動化（日付=今日、支払者=前回の人をデフォルト選択）  
   → 入力すべきは「変わることが多い情報」だけにする  

4. **モードレス操作**  
   状態を切り替えず、常に同じフローで操作できる  
   → 例えば「金額入力 → 保存」までを1画面で完結（別画面に遷移しない）

## 2. 画面構造と遷移

### レイアウト構成
- ヘッダー：ログインユーザ表示（MVPでは手動切替、本番では認証連携）  
- メイン1：画面タイトル／サマリー（残高表示、清算状況）  
- メイン2：主要コンテンツ（リスト、フォーム、差額など）  
- サブメイン：補足情報が必要なときのみ使用（MVPでは未使用、将来拡張用）  
- メイン3：主要アクション（保存・清算などの大ボタン、常時下部固定）  

👉 「上に状況、下に操作」で統一  

### 画面遷移
- ホームを基点に全画面へ遷移可能  
- 入力／詳細／清算は完了後に必ずホームへ戻る  
- 戻る操作はブラウザ標準の「戻る」で対応可能  

### 一覧と詳細のルール
- **ホーム一覧**：カテゴリ・日付・支払者・金額（最小情報で即確認）  
- **詳細画面**：補足情報（メモ、登録者、最終更新）＋編集／削除操作  
- **役割分担**：一覧＝「見る」、詳細＝「操作する」  

### ナビゲーション
- ナビゲーションバーは不要（MVPではシンプルさ優先）  
- ホームに集約  
- ＋ボタン＝入力画面  
- 支出タップ＝詳細画面  
- 清算ボタン＝清算画面  
- 右上⚙️＝設定画面

## 3. 共通UI要素

### ＋追加（FAB）
- 位置：ホーム右下に固定（スクロール追従）  
- 形状：円形／影あり、アイコン「＋」  
- サイズ：直径 56px以上、アイコン 24px  
- タップ領域：44px四方以上  
- 操作：タップで「支出入力画面」へ遷移  
- 押下フィードバック：色の濃淡変化＋リップル（200ms程度）  

### 設定（⚙️）
- 位置：ホーム右上ヘッダー内  
- サイズ：ボタン 32–40px、アイコン 24px  
- 操作：タップで「設定画面」へ遷移（MVPは Coming Soon 表示）  
- 強調度：主要動線ではないため低強調（テキストなしアイコン）  

### 保存ボタン／清算ボタン（主要アクション）
- 位置：画面下部フル幅で常時固定（メイン3）  
- 高さ：48–56px、角丸  
- 色：**緑（前向きアクション）**＋白文字、非活性時は減彩  
- 文言：動詞＋目的（例：「保存する」「清算する」）  
- 無効条件：必須未入力・金額0円時は disabled  
- 押下フィードバック：色濃く／押下アニメ（150–200ms）  
- セーフエリア：iOSの env(safe-area-inset-bottom) を考慮  

### 削除ボタン（破壊的アクション）
- 配置：詳細／編集画面の二次アクション領域（主要ボタンとは分離）  
- スタイル：赤のテキスト or アウトライン、小さめ  
- 確認：必ず確認ダイアログ  
- 文言例：「この支出を削除しますか？」  
- ボタン配置：左「キャンセル」、右「削除する（赤）」  
- 実行後：トーストで「削除しました」を表示  

### 入力欄（フォーム一式）
- 構成：ラベル／入力フィールド／エラー表示 を縦並びで統一  
- 間隔：フィールド間 12–16px、タップ領域 44px以上  
- エラー：フィールド直下に赤文字・短文（例：「金額を入力してください」）  
- 数字入力：アプリ内テンキー入力、桁区切り表示 
- アクセシビリティ：ラベルは for と id を対応、必須には「必須」表示  

### トースト通知（成功／注意／エラー）
- 位置：ヘッダー直下（上部中央）、上端から 8–16px  
- 表示時間：成功 2秒／エラー 3–4秒、タップで即閉  
- 色：成功=緑、注意=黄、エラー=赤（背景は半透明＋軽い影）  
- 挙動：フェード＋軽いスライド（~200ms）、同時は1件のみ（差し替え）  
- アクセシビリティ：`aria-live="polite"`、フォーカスは奪わない  
- セーフエリア：上部 env(safe-area-inset-top) を考慮  

### アイコン運用
- 基準：Material Icons 等に合わせ 24px を基本  
- 例：FAB内=24px／ヘッダー⚙️=24px／行内アイコン=20–24pxで統一  
- 一貫性：線幅・スタイル（アウトライン/フィル）を画面内で混在させない  

### 重なり順（z-index）と重なり回避
- トースト ＞ 固定ボタン（保存/清算/FAB）＞ コンテンツ  
- トーストやキーボード出現時でも主要アクションが隠れない  

### 最小タップサイズ
- すべてのタップ可能要素は 44×44px 以上（実寸 or ヒット領域で確保）  
- 一覧行は行全体をタップ領域にして詳細画面へ遷移可能

## 4. ビジュアルルール（カラー・フォーマット）

### カラー
- **ユーザー識別（MVP）**  
  - Aさん＝青 🟦  
  - Bさん＝オレンジ 🟧  

- 適用範囲：差額サマリー、支払者表示、清算画面など  
- **アクション色**  
  - 保存・清算＝緑  
  - 削除・キャンセル＝赤  

- **背景**  
  - 白ベース＋広めの余白、フラットデザイン  

### フォーマット
- 日付：YYYY/MM/DD  
- 金額：3桁区切り＋「円」（例：1,200円）  
- 差額表示：「AさんがBさんに◯円」固定文言  
- カテゴリ：アイコン＋名前（例：🍔 食費）  

---

## 5. 入力ルール
- 日付：デフォルト「今日」、クイック「昨日」ボタン  
- 支払者：ログイン中のユーザを保持  
- カテゴリ：5つのみに固定  
- 金額：電卓ライク（アプリ内テンキー）、桁区切り表示、0円は保存不可  
- メモ：任意入力（空でも保存可）  

---

## 6. エラーハンドリング＆通知
- エラーは短文で明確に（例：「金額を入力してください」）  
- 入力欄直下に赤文字で表示  
- モーダル確認は使用しない  
- 成功時はトースト通知で即時フィードバック  
- 例：「保存しました」「削除しました」「清算しました」  

---

## 7. 個別画面のルール（清算画面）
- 差額は常に自動計算して表示  
- 「清算する」ボタンは大きく明示（主要アクションルールを適用）  
- 実行後は即処理 → トースト通知で結果表示  
- 清算履歴をリスト形式で表示（直近3件＋「もっと見る」）  
- 清算済みは履歴に残すが、ホーム画面では非表示
